# 双语品牌与可索引英文站设计

日期：2026-08-24
状态：已确认；本地实施与验收完成，尚未提交或部署

## 目标

在保留现有中文网址和搜索入口的前提下，为官网提供可由搜索引擎、AI 爬虫和普通浏览器直接读取的英文页面。中文页面使用“实解智能”，英文页面使用 **SolveReal Systems**；结构化数据将两者声明为同一个公开品牌。

完成后的用户可观察结果：

- 中文页面继续通过现有网址访问，内容和品牌表现不回退。
- 英文核心页面通过 `/en/...` 独立网址访问和刷新，原始 HTML 已是英文。
- 语言切换会导航到对应语言网址，而不是只修改浏览器内状态。
- 搜索引擎能通过 canonical、`hreflang`、站点地图和 JSON-LD 识别双语页面及同一品牌关系。
- 只有存在审核后英文正文的文章才生成英文文章页。

## 范围

本设计覆盖：

- 双语品牌名称与公开英文定位。
- 中文现有路径和 `/en` 英文路径的路由关系。
- 页面语言、元数据、结构化数据、站点地图和语言切换。
- 英文文章的发布门槛。
- 桌面端、移动端和原始 HTML 验收。

本设计不覆盖：

- 自动翻译或批量翻译现有中文文章。
- 发明英文公司主体、客户、案例、指标、地址或其他未经审核的公开事实。
- 按 IP 自动选择语言、强制地区跳转或针对单一国家推广。
- 重新设计现有视觉系统、导航信息架构或后台访问检测。
- 本轮设计确认本身不授权 Git 提交、推送或生产部署。

## 方案选择

### 品牌方案

采用按语言分别展示的同一品牌：

- 中文公开名称：`实解智能`
- 英文公开名称：`SolveReal Systems`
- 英文品类表达：`Enterprise AI Systems Design & Delivery`
- 英文核心表达：`We design and deliver practical AI systems that solve real business problems.`

未采用逐字拼音，因为它不能帮助海外客户理解业务；未采用 `SolveReal AI`，因为 `Systems` 更准确地覆盖企业 AI 系统设计、交付和未来扩展。

### 网址方案

采用“不迁移中文、只增加英文前缀”的方案：

- 中文：`/`、`/services`、`/projects`、`/projects/[id]`、`/articles`、`/about`、`/contact`
- 英文：`/en`、`/en/services`、`/en/projects`、`/en/projects/[id]`、`/en/articles`、`/en/about`、`/en/contact`

该方案保留现有中文链接和收录，不引入 `/zh` 迁移。`/` 始终是中文默认页，不根据 IP 或浏览器语言自动重定向。

## 架构与数据流

### 1. 路由是语言权威

当前网址决定页面语言：无 `/en` 前缀为中文，带 `/en` 前缀为英文。服务端渲染必须依据路由输出对应的 `<html lang>`、导航、正文、元数据和结构化数据。

浏览器中保存的语言偏好只能改善后续体验，不得覆盖当前网址，也不得导致刷新后网址、HTML 和可见语言不一致。

### 2. 集中式品牌配置

品牌配置为中英文名称、定位和描述的唯一来源。页面组件、metadata、Open Graph、JSON-LD、站点地图相关标题以及机器可读品牌文件均从该配置派生，避免分别硬编码。

`DESIGN.md` 在实施时同步更新：删除“不设置独立英文品牌名”的旧规则，正式记录“实解智能 / SolveReal Systems”的按语言展示合同。

### 3. 页面对应关系

每个存在真实双语内容的页面都有明确对应路径。语言切换器优先导航到当前页面的另一语言版本，例如：

- `/services` ↔ `/en/services`
- `/projects/example` ↔ `/en/projects/example`
- `/about` ↔ `/en/about`

对于没有审核英文译文的中文文章，不生成 `/en/articles/[slug]`。从此类中文文章切换英文时进入 `/en/articles`，由英文文章索引展示当前真正可用的译文，不制造不存在的对应页。

## 搜索与机器可读设计

### Canonical 与语言声明

- 中文页面 canonical 指向自己的中文网址。
- 英文页面 canonical 指向自己的 `/en/...` 网址。
- 有真实双语版本的页面互相声明 `hreflang="zh-CN"` 和 `hreflang="en"`。
- `hreflang="x-default"` 指向对应中文默认页。
- 没有英文版本的中文文章不输出英文 `hreflang`。

### 站点地图

站点地图只列出实际可访问并允许收录的页面。双语页面包含语言对应关系；单语文章只列中文网址。不得为了保持数量对称而创建空白、重定向或中文正文包装的英文页面。

### 品牌结构化数据

中英文页面引用同一个稳定的品牌实体 ID：

- 中文页面：`name` 为 `实解智能`，`alternateName` 包含 `SolveReal Systems`。
- 英文页面：`name` 为 `SolveReal Systems`，`alternateName` 包含 `实解智能`。
- 页面语言和可见内容保持一致，必要时声明相应 `inLanguage`。

此关系仅表达同一公开品牌的双语名称，不声明未证实的独立英文法律实体。

### 原始 HTML

英文页面的标题、描述、导航、主要正文和 JSON-LD 必须存在于服务端返回的原始 HTML 中。Google、Bing 和 AI 爬虫不需要执行语言切换脚本即可获取英文内容。

现有 `robots.txt`、`llms.txt`、`brand-facts.json` 和 `/ai/*.json` 继续遵循同一审核事实来源；只加入真实存在的英文入口和英文品牌名称，不改变现有爬虫准入策略。

## 交互与异常处理

- 语言切换是可访问的真实链接或等价导航控件，可被键盘使用并清楚标注目标语言。
- 普通页面切换后保持当前内容语义和路径。
- 未翻译文章切换英文时进入英文文章索引，不返回 404，也不冒充该文章已有英文版。
- 请求不存在的英文路径时沿用标准 404 行为，不静默退回中文正文。
- 英文内容缺失时构建或内容解析应失败关闭，避免产生中英混杂页面。
- 不按访客 IP 强制跳转，避免错误地区判断、缓存分裂和搜索爬虫看到不稳定内容。

## 验收标准

### 自动化与构建

- 品牌配置测试覆盖两种语言名称及同一实体关系。
- 路由/metadata 测试覆盖中文与英文 canonical、`hreflang`、Open Graph locale 和 `<html lang>`。
- 站点地图测试证明只包含真实页面，并正确处理无英文译文的文章。
- 语言切换测试覆盖普通对应页和未翻译文章两条路径。
- 既有 architecture audit、project evidence audit、lint、typecheck、测试和生产构建通过。

### 真实入口

在本地生产构建中验证：

- 直接打开并刷新中文、英文首页和至少一个核心内页。
- 查看原始 HTML，确认英文页面无需客户端切换即可读取英文内容及英文 metadata。
- 检查 canonical、`hreflang`、JSON-LD 和站点地图中的完整绝对网址。
- 在 1440×900 与 390×844 下检查导航、品牌名、语言切换、换行和页面级横向溢出。
- 验证中文现有网址仍可访问，未翻译文章没有伪英文页面。

部署只有在用户另行明确授权后执行；本地构建成功或 HTTP 200 不单独证明生产收录或搜索曝光已经发生。

## 完成边界

本功能的实施完成条件是：双语核心页面可在真实本地入口直接访问，服务器原始 HTML 与网址语言一致，品牌及 SEO 声明正确，文章翻译门槛被确定性执行，现有中文路径无回归。

搜索引擎何时抓取、收录和提升排名属于外部结果，需要部署后的 Search Console/Bing Webmaster 和真实爬取数据单独观察，不能由本地实现直接保证。
