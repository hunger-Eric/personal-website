# 实解智能官网曝光增长计划

更新日期：2026-08-24
正式域名：`https://me.itheheda.online`
范围：中文保留现有路径，英文使用 `/en`；阶段一实施，阶段二至四仅规划
当前状态权威：`docs/PROJECT-STATE.md`（本文不复制或替代发布状态）

## 1. 总目标与非目标

总目标是在已有双语网站与技术可发现性基础上，建立“可验证、可持续、不过度承诺”的全球搜索曝光增长流程：搜索引擎能够发现规范 URL；团队能够分别观察收录、曝光、点击与咨询；内容与外部分发始终受事实审核和反垃圾边界约束。

非目标：不重做现有 robots、sitemap、canonical、hreflang、JSON-LD、`llms.txt`、Feed 或访问检测；不购买、交换或批量制造外链；不批量翻译未审核内容；不以提交 sitemap/IndexNow 冒充收录；不承诺关键词排名、流量或咨询数量；本计划不授权部署、账号变更、真实 URL 提交、发布或 Git 写操作。

## 2. 当前基线

### 2.1 已完成的技术可发现性

- 网站已具备中文正式路径、`/en` 英文核心页、robots、sitemap、canonical、hreflang、JSON-LD、`llms.txt`、RSS/JSON Feed 与访问检测。
- 内容库现有 8 篇已发布中文文章；当前没有经过人工审核的英文文章详情，因此 `/en/articles` 是英文文章入口，不生成未审核英文详情 URL。
- 2026-08-24 对正式响应的只读审计：`/robots.txt`、`/sitemap.xml`、`/`、`/en`、`/services`、`/en/services`、`/articles` 和一篇代表性文章均返回 HTTP 200；robots 指向正式 sitemap；sitemap 含 38 个 URL，中文/英文核心页带 `zh-CN`、`en`、`x-default` alternate；抽检页面 canonical 均指向正式域名。文章详情保持中文单语，不伪造英文 alternate。
- 上述只证明正式技术响应可读，不证明 Google/Bing 已处理 sitemap、已抓取、已收录或产生曝光。

### 2.2 尚缺的业务与平台证据

- 尚无本任务可访问的 Google Search Console 或 Bing Webmaster Tools 账号回执，站点所有权、sitemap 状态、URL Inspection 和平台搜索表现均不能声称已完成。
- 公开搜索可见性仍弱：目前缺少平台内可复核的查询、页面、国家/地区、曝光与点击基线，不能从 `site:` 查询或站内访问日志反推完整收录率。
- 站内访问检测与搜索平台的口径不同：前者记录到站后的聚合请求，后者才是搜索结果展示与点击的权威。

## 3. 指标分层：五种状态不得混写

| 层级 | 含义 | 权威证据 | 不能推出 |
| --- | --- | --- | --- |
| 代码完成 | 本地或已部署代码能输出预期标记/路由/安全门 | diff、测试、构建、正式响应 | 搜索引擎已看到 |
| 搜索引擎收录 | 平台确认某 URL 在索引中 | Search Console/Bing URL Inspection、索引报告 | 一定有展示 |
| 曝光 | URL 在用户搜索结果中出现 | 平台 Performance/Search Performance impressions | 用户点击或咨询 |
| 点击 | 用户从搜索结果进入网站 | 平台 clicks；站内只作趋势交叉验证 | 有效商机 |
| 咨询转化 | 用户提交联系表单或经可归因入口发起咨询 | 站内聚合转化事件/业务 CRM，遵守隐私边界 | 由单一关键词或单次点击必然导致 |

周报必须逐层报告，不用 HTTP 200、提交成功、IndexNow 200 或访问日志替代下游结果。

## 4. 阶段一：站长平台、收录信号与基线

### 输入

- 正式域名和当前 sitemap；Google/Bing 控制台为该站点生成的公开验证值；IndexNow key；关键 URL 清单；具备相应权限的账号操作者。
- 当前官方协议：[Google 所有权验证](https://support.google.com/webmasters/answer/9008080)、[Google sitemap 报告](https://support.google.com/webmasters/answer/7451001)、[Google URL Inspection](https://support.google.com/webmasters/answer/12482179)、[Bing IndexNow 接入](https://www.bing.com/indexnow/getstarted)。

### 允许改动面

- root metadata 的环境变量验证入口；固定 key 验证路由；同源公开路径白名单、payload 构造与通知脚本；测试、`.env.example`、README、本计划和 `docs/PROJECT-STATE.md`。
- 不修改既有 robots/sitemap/canonical/hreflang 生成逻辑，除非正式审计发现明确缺陷并另行获批。

### 完成证据

- 代码侧：空环境不输出验证标签；配置后输出 Google `google-site-verification` 与 Bing `msvalidate.01`；合法 key 在 `/indexnow-key.txt` 以纯文本返回；非法/缺失 key 返回 404。
- 安全侧：IndexNow 只接受正式 HTTPS 同源、无 query/hash、公开路径白名单 URL；默认 dry-run 不调用外部端点；真实提交需 `--submit` 与 `INDEXNOW_ALLOW_SUBMIT=true` 双门。
- 回归侧：定向 RED/GREEN 证据，以及 architecture audit、project evidence audit、lint、typecheck、完整测试、生产构建。
- 账号侧（需授权后）：两平台所有权状态、sitemap “成功/已处理”回执、关键 URL Inspection 状态、Search Performance 初始导出或截图日期范围。平台收到通知与实际收录分别记录。

### 外部权限门

部署环境变量、触发部署、登录 Google/Bing、创建/验证 property、提交 sitemap、请求 URL 索引、真实 IndexNow 提交都需要用户单独授权。公开验证值不是账号密码，但仍只能由控制台生成并经环境变量注入，不写死到仓库。

### 停止条件

验证值来源不明、正式域名/property 不一致、需要 DNS 改动但无域名权限、sitemap/关键 URL 响应不符合当前基线、URL 不在正式同源白名单、真实提交未获授权，或平台证据与代码/正式响应冲突时立即停止。

### 最小账号作业清单（当前未执行）

1. Google Search Console 中创建 `https://me.itheheda.online/` URL-prefix property（如选择 Domain property，则必须走 DNS，超出本地实现范围）。复制 HTML tag 的 `content` 值到部署环境 `GOOGLE_SITE_VERIFICATION`。
2. Bing Webmaster Tools 中添加同一正式站点，复制 meta tag 的 `content` 值到 `BING_SITE_VERIFICATION`。
3. 另行授权部署后，在正式首页原始 HTML 中核对两个 meta；再分别点击 Verify，并保存 property、时间和结果回执。
4. 在两平台提交 `https://me.itheheda.online/sitemap.xml`，记录“已提交”与后续“成功/已处理”状态，二者不可合并。
5. 各平台抽检 `/`、`/en`、`/services`、`/en/services`、`/articles`、最新中文文章和 2 个项目页；记录 discovered/crawled/indexed/canonical 状态。只有平台允许且另获授权时才请求索引。
6. 为 IndexNow 生成合规 key，注入 `INDEXNOW_KEY` 并部署；先确认正式 `/indexnow-key.txt` 内容精确匹配，再对实际新增/更新/删除的 URL 另行授权一次真实提交。不要补提历史多年未变化 URL。

## 5. 阶段二：中英文高意图内容集群与审核边界（仅计划）

输入为阶段一查询/页面/国家数据、真实销售问题、服务边界和公开项目证据。中文优先覆盖真实客户问题；英文不是逐字翻译，而是面向全球买家的独立检索意图与术语校准。

当搜索平台仍在生成首批数据时，经用户明确批准，可以先根据真实服务边界、公开项目证据和现有内容缺口制作“待搜索数据校准”的假设型 brief。此类 brief 不得声称搜索量或客户需求已经得到平台证明，不得据此创建 MDX 正文或发布 URL；平台数据可用后必须重新校准主题、语言、国家和优先级。2026-08-24 的首批 4 个中文、2 个英文 brief 见 `docs/superpowers/plans/2026-08-24-stage-two-content-briefs.md`。

- 允许改动面：经审核的内容 brief、MDX 正文、内部链接与必要 metadata；项目事实仍由现有公开事实配置管理。英文详情仅在事实、术语、引文、承诺边界和 CTA 全部经人工审核后发布。
- 完成证据：每篇内容有目标读者、主问题、证据来源、内部链接、人工审核人、发布回执及发布后 URL；平台收录另列。
- 外部权限门：模型/检索调用、内容发布、第三方材料引用均需对应授权和版权/事实审查。
- 停止条件：缺少一手证据、英文只能机械翻译、主题与真实服务不一致、需要虚构客户或效果数据、或内容只是改写关键词。

## 6. 阶段三：外部分发、真实引用与反垃圾外链（仅计划）

输入为已发布且有独立价值的文章/案例、真实合作关系和目标受众渠道。允许制作与原文一致的摘要、社区回答、合作方资源页或行业目录资料，并使用可追踪但不伪装的链接。

- 完成证据：记录渠道、受众、发布日期、公开 URL、引用上下文、是否由第三方自主保留及对应落地页。只有可公开访问、语义相关且真实编辑产生的第三方引用才计入“真实引用”。
- 外部权限门：任何发帖、邮件、合作邀约、目录提交或付费赞助均逐渠道授权。
- 停止条件：购买链接、PBN、群发客座文、隐藏链接、评论垃圾、虚假账号、自导自演媒体报道、以 do-follow 数量为目标的交换，或渠道要求误导披露/承诺效果。

## 7. 阶段四：Search Console + 站内聚合数据周反馈闭环（仅计划）

输入为 Google/Bing 的查询、页面、国家、曝光、点击、收录状态及现有隐私边界内的站内聚合访问/咨询数据。允许新增周度只读投影或报表入口，但必须引用平台导出和站内权威，不复制成第二套可写状态。

- 完成证据：每周固定日期输出数据区间与时区、平台覆盖、收录变化、曝光/点击变化、落地页到咨询漏斗、异常解释和下周最多 3 个可验证动作。Search Console 是 Google 搜索表现权威，站内聚合是到站后行为线索，两者不强求数值一致。
- 外部权限门：平台 API/OAuth、数据导出、共享报表或消息发送需单独授权；凭据不可进入仓库或日志。
- 停止条件：数据延迟、权限缺口、口径变化、采样/隐私风险或无法关联咨询来源时标为未知，不补算或猜测。

## 8. 30 天可量化目标

以下是团队可控制的执行/观测目标，不是排名、流量或收录承诺；账号权限未到位时相应项标记为阻塞，不伪造完成。

| 截止 | 可量化目标 | 验收口径 |
| --- | --- | --- |
| 第 3 天 | 2 个平台 property 身份和权限明确；正式 sitemap 各有 1 条提交/处理记录 | 控制台回执；无权限则有责任人和阻塞状态 |
| 第 7 天 | 为 sitemap 的 38 个当前 URL 建立平台状态盘点；至少抽检 12 个关键 URL，覆盖中英首页、服务、项目、文章入口和中文文章 | URL Inspection/索引报告日期化记录，不用 `site:` 查询代替 |
| 第 7 天 | IndexNow key 正式可读；对当期真实变更 URL 的 dry-run 覆盖率 100%，异域/私有路径接受数为 0 | 正式 key 响应与安全检查；真实提交仍需授权 |
| 第 14 天 | 建立首个 28 天或平台可提供最大区间的查询、页面、国家、曝光、点击基线 | 原始导出/截图 + 日期、时区、过滤条件 |
| 第 21 天 | 完成至少 6 个高意图内容 brief（中文不少于 4、英文不多于 2），每个绑定真实问题与证据审核人；是否发布另行审批 | brief 审核记录；不要求抢发文章 |
| 第 30 天 | 形成 4 次周度快照；每次至多 3 个后续动作，并能分别报告代码、收录、曝光、点击、咨询 | 日期化周报与来源链接；缺失数据明确为未知 |

排名、曝光量、点击量和咨询量只记录实际值及趋势，不设保证值。30 天后是否进入下一阶段，以阶段一账号基线和审核能力为入口，而不是以“提交完成”自动推进。

## 9. 阶段切换与下一入口

阶段二正文与发布入口必须同时满足：阶段一代码获得单独部署授权并完成正式响应复核；至少一个搜索平台形成可用基线；内容主题能够绑定真实业务问题和公开证据；用户明确批准内容生产/发布范围。平台基线形成前只允许制作经用户批准、明确标注“待搜索数据校准”的假设型 brief，不得提前生成或发布 MDX 正文、开展外链分发或建立自动周报。真实 IndexNow 提交仍按阶段一的独立外部权限门执行。
