## 直接答案

当官网首页、服务页、旧文章和英文版对同一项能力写出不同条件时，GEO 的第一项工作应当是确认哪条说法仍然成立，以及谁有权确认。继续增加文章、Schema 或外链，可能让更多页面被发现，却不会替企业判断哪个承诺是真的。

比较稳妥的做法，是为每一项会影响购买决定的公开事实建立一条记录。记录中要有经过确认的表述、事实负责人、公开证据页、适用条件、生效与复核日期、受影响页面，以及中文和英文版本的同步状态。页面仍然可以采用不同写法，核心条件必须来自同一条记录。

这篇文章讨论的是网页进入搜索与 AI 回答之前的内容治理。关于网页怎样被检索和使用，可参阅[从一个问题到带来源的回答](/articles/from-prompt-to-answer-how-text-llms-work)；关于改动后怎样观察效果，可参阅[官网被 AI 引用以后，怎么判断 GEO 改动有没有用](/articles/how-to-measure-geo-ai-citations)。这里不重复检索流程和效果归因，只处理一个更早的问题。官网怎样保持一套可核对的公开事实。

## 一项服务变化怎样留下四种公开说法

下面是一个假设例子，不代表本站客户项目。

一家公司原先只接收表格文件，后来增加了扫描件识别。真实服务条件是扫描件需要先做文字识别，关键结果仍由人复核。服务页已经更新，首页却保留着“全自动处理所有文件”的旧文案；英文页还写着“不支持扫描件”；半年前的文章则把试用中的能力写成即将上线。

这四个页面都能被访问。买家从搜索结果、旧链接或 AI 回答进入任意一页，都可能得到不同结论。此时，canonical 标签只能帮助搜索系统在重复或高度相似的 URL 中选择代表页。[Google 对 canonical 的说明](https://developers.google.com/search/docs/crawling-indexing/consolidate-duplicate-urls)没有赋予它判断业务事实真伪的能力。页面内容已经不同，单靠 URL 规范化也无法完成纠错。

更有效的起点，是把“支持扫描件”拆成一条带条件的主张。扫描件可接收，文字识别先执行，关键结果需要人工复核。负责服务交付的人确认这条事实，服务页成为公开证据页，其他页面再按各自语境引用或概括。以后条件变化时，团队能够查到哪些页面依赖它。

## 先为主张建立一张公开事实记录

公开事实记录不必先做成复杂系统。一张受控表格或仓库中的结构化文件就能起步。关键在于每个字段都能回答复核问题。

| 字段 | 要回答的问题 | 最低要求 |
| --- | --- | --- |
| 事实编号与批准表述 | 团队正在维护哪一项主张 | 一项事实一个稳定编号，保留必要条件 |
| 事实负责人 | 谁能确认它仍然成立 | 写到具体岗位或负责人，不能只写“市场部” |
| 公开证据页 | 外部读者在哪里核对 | 指向当前可访问并经过确认的页面 |
| 适用范围 | 哪些客户、地区、版本或输入符合条件 | 把限制写入正文，不能只留在内部备注 |
| 证据状态 | 这是已上线能力、计划还是第三方结论 | 不把计划、试验和已交付能力混写 |
| 时间状态 | 何时生效，何时复核，何时退役 | 至少保留生效日期和下一次复核日期 |
| 依赖页面 | 哪些页面、结构化数据或资料复用了它 | 包含首页、服务页、文章、FAQ 和下载资料 |
| 语言版本 | 中文和英文是否表达同一条件 | 各语言可自然改写，事实范围保持一致 |

[W3C 的 PROV-O](https://www.w3.org/TR/prov-o/)用实体、活动和责任主体描述信息来源与变化。企业官网无须为了 GEO 实施整套本体标准，但可以借用这个思路。公开说法是一项可追溯的信息，修改是一次有记录的活动，批准人承担确认责任。这里引用 PROV-O 只是内容治理方法，不表示搜索或 AI 平台会按该模型给页面加分。

事实记录还需要区分“权威证据页”和“最想获得流量的页面”。前者负责完整说明当前事实，后者可能是首页、行业方案或文章。两者可以是同一页，也可以分开。若一篇文章为了阅读流畅只写了简短结论，它应链接到能说明条件的证据页，不能自行创造更宽的承诺。

## 一次事实变更怎样穿过整个网站

内容变更可以按一次小型发布来管理。先由事实负责人确认变化，再寻找依赖这条事实的所有公开位置。搜索范围不应只限于正文，还要检查标题与摘要、FAQ、JSON-LD、下载资料、站点内搜索数据，以及另一种语言的页面。

可见正文与结构化数据必须一起检查。[Google 的结构化数据政策](https://developers.google.com/search/docs/appearance/structured-data/sd-policies)要求标记内容反映用户可见的信息，并保持相关和最新。若正文已经改成“需要人工复核”，JSON-LD 或 FAQ 标记仍写“全自动”，机器可读层仍在传播旧条件。

更新时间也要有事实依据。[Google 的日期说明](https://developers.google.com/search/docs/appearance/publication-dates)建议让页面上的可见日期与 `datePublished`、`dateModified` 等结构化日期保持一致。仅仅调整页脚或换一张图片，不应把旧文章包装成全新事实。对于 sitemap，[Google 只会在 `<lastmod>` 持续且可验证地准确时使用它](https://developers.google.com/search/docs/crawling-indexing/sitemaps/build-sitemap)。因此，更新时间要对应实质内容变化。

重大事实已经发布后，可以通知支持相关协议的搜索系统。[IndexNow 的官方 FAQ](https://www.indexnow.org/faq)允许提交新增、更新或删除的 URL，也明确不建议反复提交没有变化的页面。提交只是一项发现信号，不保证立即抓取、收录或展示。

最后保留发布记录。它至少要写明事实编号、批准人、修改页面、语言版本、发布日期和待复核项。以后再发现旧说法时，团队能判断它是漏改、缓存、第三方转载，还是尚未完成的语言版本。

## 哪些冲突应该先处理

页面文字差异带来的风险并不相同。标题里少一个形容词，通常低于以下几类冲突。

| 冲突类型 | 可能造成的实际问题 | 建议优先级 |
| --- | --- | --- |
| 购买资格和服务范围 | 买家误判自己是否适用 | 高 |
| 价格、地区和交付时间 | 产生错误预算或进度预期 | 高 |
| 人工复核、安全与隐私条件 | 隐去必要控制和责任边界 | 高 |
| 产品状态与版本要求 | 把计划、测试或旧能力当成当前能力 | 高 |
| 品牌名称和主体身份 | 中英文页面指向不同公司或产品 | 高 |
| 不影响事实的表达差异 | 文风不同，但条件一致 | 低 |

排序时可以看四个因素。错误是否改变购买决定，是否扩大企业承诺，出现在哪些高访问页面，旧版本已经存在多久。这个顺序比“先改排名最高的页面”更稳妥，因为低流量页面仍可能成为一条回答的直接来源，也可能被销售或合作伙伴长期引用。

## 双语页面需要共享同一项事实

中英文官网最容易出现的缺口，是把翻译当成一次性工作。中文服务页更新后，英文页仍停留在旧版本；或者英文为了简洁删掉了适用条件，结果把有限能力改写成普遍承诺。

每个语言版本应引用同一个事实编号，并分别保存本地化表述、审核人和发布日期。[Google 的多语言页面指南](https://developers.google.com/search/docs/specialty/international/localized-versions)建议每个语言版本列出自己和其他语言版本，并建立双向的 `hreflang` 关系。这能帮助搜索系统识别页面对应关系，却不能让两个版本中的业务说法自动一致。内容一致性仍由事实负责人和语言审核人完成。

如果不同地区确实有不同价格、法规或服务范围，就建立带地区条件的两条事实记录。不要为了追求逐句相同，抹掉真实差异。验收只看条件能否追溯，逐句相同没有必要。

## 适用边界

这套方法适合公开服务能力、价格规则、产品状态、身份信息和已经批准公开的项目事实。客户保密信息、账号内数据、尚未批准的路线图和无法核实的成果不应进入公开事实库。

事实一致也不保证页面会被任何平台收录或引用。以 OpenAI 为例，[OAI-SearchBot 的官方说明](https://developers.openai.com/api/docs/bots)把它定义为用于搜索结果展示的爬虫控制；允许访问只影响页面被发现和考虑的资格，不构成引用承诺。其他平台也有自己的抓取、索引和展示规则。

这套记录同样不能代替法律、合规或专业审查。高风险陈述应由对应责任人批准。外部平台仍可能使用旧缓存、第三方页面或其他来源，团队只能保证自有公开页面有清晰、当前且可核对的事实。

## 实施步骤

1. 选出十到二十项会改变购买或交付判断的公开事实，优先覆盖服务范围、必要条件、价格规则、产品状态和人工责任。
2. 为每项事实指定负责人、批准表述、公开证据页、适用范围、生效日期和复核日期。
3. 搜索整个官网和公开资料，登记复用该事实的中文页面、英文页面、结构化数据与下载内容。
4. 按风险先修改会造成错误承诺的页面，再处理不影响判断的表达差异。
5. 发布时同步可见正文、结构化数据、页面日期与 sitemap 时间，并记录仍待更新的位置。
6. 对重大更新提交发现通知，随后检查公开页面、语言切换和目标问题下的实际回答，不把提交回执当成引用结果。

## 验收清单

- 每项高风险事实都有可识别的负责人和公开证据页。
- 服务范围、限制和人工责任在可见正文中完整出现。
- 首页、服务页、FAQ、文章和结构化数据没有相互冲突的当前说法。
- 中文与英文页面引用同一事实编号，真实的地区差异有单独条件。
- `dateModified` 与 sitemap 的更新时间对应实质修改。
- 旧页面已经更新、重定向、删除或明确标为历史内容。
- 发布记录能说明谁批准了什么，哪些页面已经同步，哪些事项仍待复核。

## 下一步

[Open GEO Console](https://geo.itheheda.online/zh)可以从公开页面和目标买家问题出发，检查访问、表述、问题覆盖与引用证据缺口，并把问题整理成页面级整改优先级。它不会替企业决定哪项业务事实是真的，也不会自动批准或发布修改。事实负责人仍需确认公开表述，网站负责人再执行变更。
